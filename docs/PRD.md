# PRD: crd-ime-toggle

Chrome 원격 데스크톱(CRD)으로 맥에서 맥으로 접속했을 때, 로컬 캡스락 한 번으로 원격 맥의 한/영을 전환한다.

## 1. 문제

- 로컬과 원격 맥 모두 Karabiner로 `caps_lock → F19` 를 쓰고, macOS 단축키 "다음 입력 소스 선택"(symbolic hotkey 61)을 F19로 등록해 한영을 전환한다.
- CRD 창에서 캡스락을 누르면 로컬 macOS가 F19를 시스템 단축키로 먼저 소비한다. 그래서 로컬 입력 소스만 바뀌고 원격에는 아무것도 전달되지 않는다.
- CRD가 원격에 주입하는 키 이벤트는 가상 이벤트다. 원격 Karabiner(HID 레벨)에는 보이지 않으므로 원격의 `caps_lock → F19` 규칙도 동작하지 않는다.
- 결과: 원격 작업 중 한영 전환을 하려면 원격 메뉴바를 마우스로 눌러야 한다.

## 2. 목표

- G1: CRD 앱 창에서 캡스락을 누르면 원격 맥의 입력 소스가 한/영 사이에서 토글된다.
- G2: 로컬 맥을 직접 쓸 때와 원격 맥 앞에 앉아서 쓸 때 기존 캡스락(F19) 동작은 바뀌지 않는다.
- G3: 원격 설치는 스크립트 한 번과 권한 허용 한 번으로 끝나고, 로그인할 때 자동으로 실행된다.

## 3. 비목표

- 일반 크롬 탭에서 `remotedesktop.google.com` 을 열어 쓰는 경우 (Karabiner가 탭 단위로 구분하지 못함)
- 맥이 아닌 원격 호스트 (Windows, Linux)
- 메뉴바 UI, 설정 GUI
- 3개 이상의 입력 소스 순환

## 4. 사용자 시나리오

| # | 상황 | 기대 결과 |
|---|---|---|
| S1 | 로컬 CRD 앱 창에 포커스, 캡스락 누름 | 원격 입력 소스만 한↔영 토글, 로컬 입력 소스는 그대로 |
| S2 | 로컬의 다른 앱에서 캡스락 누름 | 로컬 입력 소스 토글 (지금과 같음) |
| S3 | 원격 맥 앞에서 물리 키보드 캡스락 누름 | 원격 입력 소스 토글 1회 (중복 토글 없음) |
| S4 | 원격 맥 재부팅 후 로그인 | 프로그램이 자동 실행되어 S1 동작 |
| S5 | 원격 한/영 외에 다른 입력 소스(예: 일본어)가 선택된 상태에서 S1 | 영문으로 전환 |

## 5. 요구사항

### 기능

- F1 (로컬) CRD 앱(`com.google.Chrome.app.cmkncekebbebpfilplodngbpllndjkfo`)이 앞에 있을 때만 F19를 F18로 바꾼다. Karabiner complex rule로 구현한다. (적용 완료)
- F2 (원격) 세션 이벤트 탭으로 F18 keyDown(keycode 79)을 감지하면 한/영 입력 소스를 토글하고, 원래 이벤트는 삼킨다.
- F3 (원격) 토글 대상 두 입력 소스 ID는 설정 가능해야 한다. 기본값은 `com.apple.keylayout.ABC` 와 `com.apple.inputmethod.Korean.2SetKorean`.
- F4 (원격) 키 반복(autorepeat) 이벤트는 무시한다.
- F5 (원격) 이벤트 탭이 타임아웃이나 사용자 입력으로 비활성화되면 스스로 다시 켠다.

### 트리거 키를 F18로 둔 이유

- 원격 프로그램이 F19를 잡으면 S3에서 원격 시스템 단축키(F19)와 프로그램이 둘 다 반응해 두 번 토글될 수 있다.
- F18은 물리 키보드에서 나오지 않고 CRD 경로로만 들어오므로 충돌이 없다.

### 비기능

- N1 상주 메모리 10MB 이하, 유휴 CPU 0%
- N2 키 입력부터 전환까지 체감 지연 없음 (100ms 이하)
- N3 권한은 손쉬운 사용(Accessibility) 하나만 요구
- N4 외부 의존성 없음. Swift 표준 툴체인과 macOS 프레임워크(Carbon TIS, CoreGraphics)만 사용

## 6. 성공 기준

- S1~S5를 원격 맥에서 수동으로 확인해 모두 통과한다.
- 1일 사용 중 한영 전환 실패나 중복 토글을 체감하지 못한다.

## 7. 리스크와 미확인 사항

| ID | 내용 | 확인 방법 |
|---|---|---|
| R1 | CRD가 F18을 원격에 그대로 전달하는지 확인되지 않음 | Phase 0 스파이크: 원격에서 keycode 로거로 확인 |
| R2 | 원격 CRD 호스트가 주입한 이벤트가 세션 이벤트 탭에 잡히는지 확인되지 않음 | Phase 0 스파이크 |
| R3 | 로그인 전 화면이나 잠금 화면에서는 이벤트 탭이 동작하지 않음 | 비목표로 수용 |
| R4 | TIS로 한글 입력기를 선택한 직후 첫 글자가 이전 입력 소스로 입력되는 macOS 버그 | 필요하면 선택 뒤 짧은 지연이나 재선택으로 보정 |
| R5 | 재서명이나 재빌드 뒤 손쉬운 사용 권한이 풀림 | 설치 스크립트에서 안내 문구 출력 |
